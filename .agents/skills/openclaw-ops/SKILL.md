# OpenClaw Life Ops

This skill guides you through operating and troubleshooting OpenClaw instances
in the `openclaw-life` orchestration environment.

## Environment Layout

- `openclaw-life/` — This orchestration repo. Contains shared Traefik reverse-proxy
  and Docker network (`openclaw-life-net`).
- `openclaw-sample/` — Template directory for creating new instances. **Do not**
  edit directly; copy to `openclaw-<name>`.
- `openclaw-<name>/` — An independently cloned/deployed instance. Each is its own
  Git repository, sharing only the Docker network and Traefik proxy.
- `scripts/` — Helper scripts for the orchestration layer:
  - `openclaw-life-deploy` — Create a new instance from the sample.
  - `openclaw-life-configure` — Interactively generate `.env` for an instance.
  - `openclaw-life-check` — Pre-flight check for an instance directory.

## Critical File Locations

When investigating an instance named `<NAME>` (directory `openclaw-<NAME>`):

| File | Actual Path | Notes |
|---|---|---|
| Runtime config | `~/.openclaw-life/data/openclaw-<NAME>/openclaw.json` | **This is the file the container reads.** The repo copy (`openclaw-<NAME>/openclaw.json`) is for reference/backup only; it is **not** bind-mounted because the mount causes EBUSY errors. |
| Workspace data | `openclaw-<NAME>/workspace/` | Git-tracked and bind-mounted into the container. |
| Environment secrets | `openclaw-<NAME>/.env` | Generated by `scripts/openclaw-life-configure`. |
| Container certs | `~/.openclaw-life/certs/` | Shared across all instances, mounted read-only. |
| Traefik state | `~/.openclaw-life/data/traefik-acme.json` | ACME certificate store. |

## Troubleshooting Workflow

When the user reports an issue with an instance (e.g., model provider errors,
container not starting, WebSocket failures):

1. **Identify the instance**
   - Map the user's request to the directory `openclaw-<NAME>/`.
   - If the name isn't obvious, list `openclaw-*` directories in the project root.

2. **Check container status**
   - Run `docker ps -a --filter "name=openclaw-<NAME>"`.
   - Run `cd openclaw-<NAME> && docker compose ps`.
   - Note any `Exited`, `Restarting`, or `Unhealthy` states.

3. **Read logs**
   - Run `docker logs --tail 200 openclaw-<NAME>`.
   - Look for stack traces, connection errors, or configuration parse errors.

4. **Inspect the runtime `.env`**
   - Read `openclaw-<NAME>/.env`.
   - Verify required variables are set: `OPENCLAW_NAME`, `OPENCLAW_HOSTNAME`,
     `OPENCLAW_GATEWAY_TOKEN`, `DISCORD_BOT_TOKEN`, `INFERENCE_GATEWAY_TOKEN`, `UID`, `GID`.
   - `OPENCLAW_NAME` must match the `<NAME>` portion of the directory.

5. **Inspect the runtime `openclaw.json`**
   - Read `~/.openclaw-life/data/openclaw-<NAME>/openclaw.json`.
   - This is the authoritative configuration the container uses.
   - If a repo-local copy exists at `openclaw-<NAME>/openclaw.json`, compare them.

6. **Validate provider configuration**
   - OpenClaw uses provider names as keys. Cross-reference every `provider` field
     with the keys under `models.providers`.
   - Example: if `agents.defaults.memorySearch.provider` is `"openai"`, there must be
     a matching entry `models.providers.openai` (or whichever name is referenced).
   - Check that `baseUrl`, `apiKey`, `api`, and `models[].id` are consistent.
   - Verify environment variable placeholders like `${INFERENCE_GATEWAY_TOKEN}` are
     actually set in the container (via `.env` or shell).
   - **Validate model IDs against the inference server**:
     - Query `https://inference.labs.ai.linode.com/v1/models` (or the instance's specific `baseUrl` without the path suffix).
     - The `id` values returned by this endpoint must exactly match the `models[].id` strings in `openclaw.json`.
     - If a model ID does not appear in the server response, it is invalid and will cause provider errors.

7. **Check bind mounts and permissions**
   - The container runs as `${UID}:${GID}` (default 1000:1000).
   - Ensure `~/.openclaw-life/data/openclaw-<NAME>/` exists and is writable by that UID.
   - Ensure `~/.openclaw-life/certs/` exists and contains expected CA files if `NODE_EXTRA_CA_CERTS` is set.

8. **Check Traefik routing**
   - Verify `docker-compose.yml` labels for the instance:
     - `traefik.http.routers.<NAME>.rule=Host(\`<HOSTNAME>\`)`
     - `traefik.http.routers.<NAME>.tls=true`
     - `traefik.http.services.<NAME>.loadbalancer.server.port=18789`
   - Confirm the instance is on the `openclaw-life-net` network.

9. **Apply fixes and restart**
   - Edit the **runtime** `openclaw.json` at `~/.openclaw-life/data/openclaw-<NAME>/openclaw.json` if configuration is the issue.
   - Consider copying the fixed config back to the repo (`openclaw-<NAME>/openclaw.json`) so it is tracked in Git.
   - Restart: `cd openclaw-<NAME> && docker compose restart`.
   - Re-check logs after restart.

## Deployment Workflow

To add a new instance (only when explicitly asked):

1. Run `./scripts/openclaw-life-deploy` to copy `openclaw-sample` to `openclaw-<NAME>`.
2. Run `./scripts/openclaw-life-configure openclaw-<NAME>` to generate `.env`.
3. Optionally edit `openclaw-<NAME>/openclaw.json` (runtime path: `~/.openclaw-life/data/openclaw-<NAME>/openclaw.json`).
4. Run `cd openclaw-<NAME> && docker compose up -d`.
5. Initialize Git and push to a private remote if desired.

## Model Discovery Reference

When investigating model/provider issues, you can inspect the live catalog:

```bash
curl -s https://inference.labs.ai.linode.com/v1/models | jq '.data[].id'
```

Or, if querying from within the container (matching the container's `baseUrl`):

```bash
docker exec openclaw-<NAME> node -e "fetch('https://inference.labs.ai.linode.com/v1/models').then(r=>r.json()).then(j=>console.log(j.data.map(m=>m.id)))"
```

Any `models[].id` declared in `openclaw.json` must exist in this list.

## Safety Reminders

- Do not commit secrets (tokens, API keys) to Git.
- Do not edit `openclaw-sample/` directly — always copy via the deploy script.
- Back up `openclaw.json` before making changes: copy it to `openclaw.json.backup.<timestamp>`.
- If modifying shared Traefik config (`docker-compose.yml` in the project root), be
  aware it affects **all** instances.
